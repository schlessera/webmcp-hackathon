## Design Specificity Verdict

**LLM assessment:** Authored, not interchangeable. Eligibility trio (teal/amber/dimmed), violet=privacy, gold=committed, indigo scope ring, redacted italic-violet feed lines and the spokes wordmark form a real visual language mapping the protocol's concepts — no generic list-beside-map. But execution runs cooler than the concept: warm-paper ground barely reads against card white, header is an unstyled text row, all type system-stack small. Identity lives almost entirely in pins and badges. Concept bold; chrome timid.

**Deterministic scan:** Live in-page detector (injected `detect.js` against the running app) reported "No anti-patterns found" — the one real deterministic signal, and it corroborates the review's "clean but timid" read (no banned patterns, no clutter). The static-tree scan returned `[]` but self-declared unfit for a Vite/TSX project, and the recommended puppeteer URL scan is unavailable in this environment — count one clean signal, not two.

- E1: ≥980px layout collapses the map to zero width (MapView wrapper `<section>` in App.tsx gets no flex growth). OPEN — in polish wave.

## Overall Impression

The semantic core is genuinely strong — color-as-protocol-state, consent choreography, privacy discipline. What's missing is the layer a judge sees in the first 10 seconds: a legend that teaches the color language, human copy instead of wire enums, and one celebratory beat at the commit. Single biggest opportunity: make the map self-explanatory.

## What's Working

1. **Color-as-protocol-state** — instant visual semantics; excluded pins dim but persist, so the map never lies about the option space.
2. **Consent choreography** — violet private card → indigo "Confirm on this page" card narrates two-step delegated authority perfectly; copy is exact and humane.
3. **Privacy rendering discipline** — server-redacted lines rendered as-sent in italic violet; the UI shows it cannot reconstruct what it never received.
